# scene-author

Write each individual HTML scene composition, calibrated exactly to the locked scene durations.

## The vector recreation rule — read this first

**Screenshots are reference material. They are NOT final scene assets.**

Every UI element shown in a source screenshot — dashboards, tables, forms, buttons, modals, charts, sidebars, navigation, badges, status pills, everything — must be reconstructed as live HTML + CSS + SVG inside the scene composition. The screenshot is your visual reference; your job is to recreate its structure, hierarchy, and content as vector elements that GSAP can animate.

**Why this is non-negotiable:**

1. **Zoom integrity.** A raster screenshot blurs the moment you scale past 1×. Recreated UI stays sharp at any zoom level — critical for software/simulation walkthroughs where the camera will frequently push in on a specific element.
2. **Element-level animation.** You cannot animate a single row, value, or button inside a flattened image. You can animate any element inside reconstructed HTML.
3. **Brand consistency.** Design tokens from `design.md` must be applied to the UI — overlaying brand colours onto a screenshot looks janky; recreating with the tokens looks native.
4. **Text legibility.** Text rendered as actual text (not pixels) stays crisp at every render resolution. Screenshots blur.
5. **State transitions.** Smoothly transitioning from "table collapsed" → "row expanded" requires the same DOM to morph. Two screenshots crossfaded looks like a slideshow, not a product demo.

**What this looks like in practice for a typical walkthrough scene:**

- Screenshot shows a compliance dashboard with a table of cases, a sidebar nav, a top bar with user info.
- You build the scene as: semantic HTML structure (`<header>`, `<aside>`, `<main>` containing a `<table>`), Tailwind utility classes for layout, design tokens for colours (`var(--surface-elevated)`, `var(--primary)`, etc.), real text content from `source-flow-map.md`, SVG icons for nav items, and GSAP animations on individual rows/cells/buttons.
- You do NOT use `<img src="resources/screenshots/seq02-dashboard.png">` as the scene content.

**The exceptions** — assets that ARE used as raster:

- Character headshots from `resources/characters/*.png` (generated by image API, used as `<img>`)
- Supplied brand imagery / photography (used as `<img>` when the brief calls for evidential photography)
- Logos provided as PNG (SVG strongly preferred — if you only have PNG, use it but flag for SVG replacement)

When in doubt: rebuild as vector.

## Required HyperFrames skill invocations

Before authoring scenes, ensure you have loaded the following HyperFrames slash commands. They contain framework-specific patterns that are NOT in generic web docs:

- **`/hyperframes`** — Required. Composition patterns: `data-start`, `data-duration`, `data-track-index`, `class="clip"`, marker highlights, the full data-attribute semantics.
- **`/gsap`** — Required. GSAP timeline patterns specifically for HyperFrames — how tweens register against `window.__timelines`, easing patterns that play well with frame-by-frame render, performance considerations for the renderer.
- **`/tailwind`** — Required if the project was scaffolded with `--tailwind` (check `hyperframes.json`). Tailwind v4 browser-runtime patterns; use Tailwind utility classes for layout speed.
- **`/css-animations`** — Optional. Only if a scene uses CSS keyframes alongside GSAP (rare; prefer GSAP for consistency).
- **`/animejs`, `/lottie`, `/three`, `/waapi`** — Only if a specific scene needs them. Default to GSAP.

Invoke each relevant skill at the start of authoring so the framework rules are loaded into context.

## Steps

### Step 1 — Set up the scene-authoring loop

You will author one scene at a time, fully completing each (write → `npm run check` → fix → confirm) before moving to the next. Do not batch all scenes and then check them together — fix as you go.

For each confirmed scene in `SCENE-PLAN.md` (skip `optional` scenes unless promoted):

### Step 2 — Read the inputs for this scene

1. Read the scene row from `SCENE-PLAN.md`: ID, name, content summary, source asset(s), duration.
2. Open the referenced screenshot(s) from `resources/screenshots/` using `Read` (multimodal — you'll see the image). Study the structure: layout, hierarchy, key UI components.
3. Read the corresponding row in `source-flow-map.md` for the authoritative copy, data values, and content source flag (`brief` | `screenshot` | `⚠️ flagged`).
4. If the row is `⚠️ flagged`, do NOT proceed. Escalate to the human for placeholder content or actual content before authoring.
5. Read `ANIMATION-RULES.md` for the motion patterns to apply.

### Step 3 — Plan the recreation

Before writing any HTML, think through:

- **Structural decomposition.** What are the regions of this scene? (header, sidebar, content area, modal overlay, etc.) Map each to semantic HTML.
- **Element inventory.** List every interactive or animated element — every row, button, badge, value, label. Each will need a `data-track-index` and a position in the timeline.
- **Animation choreography.** Read `CREATIVE-DIRECTION.md` for the conventions (zoom behaviour, focus annotations, typography treatment). Plan the entrance order: what appears first, what's the focal moment, what's the exit.
- **Duration budget.** The scene runs for `[N]` seconds per `SCENE-PLAN.md`. Allocate animation time: typically 0.3–0.5s entrance, dwell period, 0.3–0.5s exit. Match the type-specific pacing from `CREATIVE-DIRECTION.md`.

### Step 4 — Author the scene HTML

Write the scene to `compositions/seq[NN]-[name].html`. Required structure:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>[Scene human-readable name]</title>
  <!-- Tailwind v4 runtime if hyperframes.json shows tailwind: true -->
  <!-- Design tokens as CSS variables in :root -->
  <style>
    :root {
      --primary: [from design.md];
      --surface-base: [from design.md];
      /* ... full token set */
    }
    /* Scene-specific styles only — global styles live in design.md guidance */
  </style>
</head>
<body data-scene="seq[NN]-[human-readable-name]">
  <!-- Vector recreation of the UI from the screenshot.
       Semantic HTML, Tailwind classes for layout, design tokens for colour.
       Every animated element has data-start, data-duration, data-track-index, class="clip". -->
  <main class="...">
    <header class="...">...</header>
    <section class="clip" data-start="0.0" data-duration="0.5" data-track-index="0">...</section>
    <table>
      <tbody>
        <tr class="clip" data-start="0.5" data-duration="0.4" data-track-index="1">...</tr>
        <tr class="clip" data-start="0.7" data-duration="0.4" data-track-index="2">...</tr>
      </tbody>
    </table>
  </main>

  <!-- GSAP timeline, paused, registered on window.__timelines -->
  <script>
    window.__timelines = window.__timelines || {};
    const tl = gsap.timeline({ paused: true });

    // Per-element animations referencing the design token easing and durations
    tl.from('[data-track-index="0"]', { opacity: 0, y: 16, duration: 0.5, ease: 'expo.out' }, 0);
    tl.from('[data-track-index="1"]', { opacity: 0, y: 8,  duration: 0.4, ease: 'expo.out' }, 0.5);
    // ... continue for every animated element

    window.__timelines["seq[NN]-[human-readable-name]"] = tl;
  </script>
</body>
</html>
```

**Hard rules — every scene file must satisfy:**

1. **`data-scene` attribute, NOT `data-composition-id`.** The scene's identifier lives on `<body data-scene="...">`. The value is `seq[NN]-[human-readable-name]` matching `SCENE-PLAN.md`.

2. **`window.__timelines`, NEVER `window.__sceneTl`.** Register the timeline on `window.__timelines["seq[NN]-[name]"]`. The other name is wrong and will silently break rendering.

3. **Every timed element has all four required attributes.** `data-start`, `data-duration`, `data-track-index`, `class="clip"`. Missing any of these will fail `npm run check`.

4. **Timeline starts paused.** `gsap.timeline({ paused: true })`. HyperFrames controls playback; the scene does not play itself.

5. **Deterministic logic only.** No `Date.now()`, no `Math.random()`, no `setTimeout` with non-fixed delays, no network fetches. The composition must produce identical output every render.

6. **Scene duration is calibrated to `SCENE-PLAN.md`.** The last animation should resolve within ±5% of the scene's target duration. Don't author a 6-second scene when the plan says 4.

7. **Design tokens, not hardcoded values.** Colours come from `var(--primary)` etc., defined in `:root` from `design.md`. Typography uses the stack from `design.md`. Motion uses the rules in `ANIMATION-RULES.md`.

8. **Content comes from the source flag.** If `source-flow-map.md` says the content source for this scene is `brief`, use the copy from `brief-summary.md`. If `screenshot`, transcribe the on-screen text from the screenshot. If `⚠️ flagged`, you should not be here.

9. **Apply creative conventions from `CREATIVE-DIRECTION.md`.** Walkthrough types: zoom-in on focus elements, callout rings, lower-third titles, measured pace. Marketing types: kinetic text reveals, fast-cut energy, full-bleed typography. Honour the type — do not default to generic motion.

10. **Accurate vs. stylised mode.** Read the flag from `CREATIVE-DIRECTION.md`. Accurate → text and layout match the screenshot verbatim; zoom lands on the actual element discussed. Stylised → copy may be simplified for clarity; zoom targets the narratively important area, not necessarily the literal element.

### Step 5 — Run `npm run check` immediately

After writing the scene, run `npm run check` (lint + validate + inspect). This is **mandatory after every individual scene**, not just at the end of all authoring.

```bash
npm run check
```

If there are errors:
- Read the error output carefully
- Fix the scene file
- Re-run `npm run check`
- Repeat until clean

Common errors and fixes:
- "Missing data-start" → add the attribute
- "Element with timing must have class=clip" → add `class="clip"`
- "Timeline not registered" → confirm `window.__timelines["..."]` assignment
- "Use of forbidden API" → remove `Date.now()` / `Math.random()` / network calls

Do NOT proceed to the next scene until `npm run check` passes for the current one.

### Step 6 — Self-verify the scene

After lint passes, do a quick functional check:

- Open the scene in preview if you have `npm run dev` running (or use `npx hyperframes inspect` to grab a snapshot).
- Verify the scene renders without console errors.
- Verify the timeline reaches its expected end position at `[duration]` seconds.
- Verify text is legible and design tokens are applied (no fallback colours visible).

### Step 7 — Loop to the next scene

Move to the next confirmed scene. Repeat steps 2–6.

### Step 8 — Final pass after all scenes

Once every confirmed scene is authored and individually passes `npm run check`:

1. Run `npm run check` once more across the whole project (no specific scene argument).
2. Verify all scene files have `data-scene` (not `data-composition-id`).
3. Verify no file uses `window.__sceneTl`. A grep for it across `compositions/` should return zero hits.
4. Verify durations sum within ±5% of the `SCENE-PLAN.md` confirmed total.

## Outputs

- `compositions/seq[NN]-[name].html` — one per confirmed scene from `SCENE-PLAN.md`

## Tools used

`Write`, `Read` (multimodal — for reading screenshots as reference), `Bash` (`npm run check`).

HyperFrames slash commands invoked: `/hyperframes`, `/gsap`, `/tailwind` (if applicable). Optionally `/css-animations`, `/animejs`, `/lottie`, `/three`, `/waapi` if a scene specifically requires them.

## Success criteria

- All `confirmed` scenes from `SCENE-PLAN.md` have an authored `compositions/seq[NN]-[name].html` file.
- Every scene file uses `data-scene` attribute (NOT `data-composition-id`).
- Every scene file registers its timeline on `window.__timelines["seq[NN]-[name]"]` (NEVER `window.__sceneTl`).
- Every timed element has `data-start`, `data-duration`, `data-track-index`, and `class="clip"`.
- `npm run check` passes with zero errors for every scene file individually, and once across the whole project after authoring is complete.
- All scene durations are within ±5% of their `SCENE-PLAN.md` targets.
- No scene file uses raster screenshots from `resources/screenshots/` as final scene content — every UI element is recreated as live HTML/CSS/SVG. Character images and brand imagery are the only raster exceptions and are used as `<img>` only where the asset manifest indicates.
- All design tokens from `design.md` are referenced via CSS variables; no hardcoded brand colours.
- Creative conventions from `CREATIVE-DIRECTION.md` (zoom, transitions, typography treatment, pacing) are applied per scene.
- For walkthrough types, the `accurate_or_stylised` mode is honoured in every scene's copy and zoom behaviour.
